# Style Guide

- Preserve the existing vRP3 module and extension conventions.
- Prefer small, focused modules and functions.
- Avoid unnecessary abstractions and global mutable state.
- Keep trusted decisions server-side.
- Name events and interfaces consistently.
- Document public APIs and compatibility expectations.
- Do not perform repository-wide formatting inside feature commits.
- CfxLua/FiveM runtime behavior overrides generic Lua tooling warnings.
